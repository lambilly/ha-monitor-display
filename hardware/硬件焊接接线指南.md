# 硬件焊接接线指南（ESP32-S3 N16R8 + 3.5寸 SPI 触摸屏）

> 依据：`ha-monitor-display.yaml` 中的实际引脚定义（固件为准），
> 结合该模组（3.5寸 320×480 ST7796S + FT6336U，14 排针 + TF 卡槽）的标准资料核对。
> 注：市面上 3.5" / 4.0" 的 ST7796S 模组引脚定义基本一致，但**以本文件表格为准**，
> 换屏后请先用万用表确认排针功能再接线。

## 一、模组识别

| 项目 | 参数 |
|---|---|
| 屏幕 | 3.5寸 IPS，320×480（横屏 480×320） |
| 显示驱动 | ST7796S（4 线 SPI） |
| 触摸驱动 | FT6336U（I2C，地址 0x38，与固件一致） |
| 供电 | **5.0 V**（数据表标称；接 3.3V 也能工作，但背光偏暗） |
| 背光电流 | 95 mA（数据表典型值） |

> 详细结构尺寸、定位孔、PCB 设计清单见同目录《3.5寸屏幕规格要点（PCB设计用）.md》。

## 二、14 针接线表（核心）

模组排针序号从 VCC 开始（丝印有标注）：

| # | 模组丝印 | 功能 | 接 ESP32-S3 | 固件配置 | 备注 |
|--:|---|---|---|---|---|
| 1 | VCC | 电源正 | **5V** | — | 接 3.3V 背光会暗 |
| 2 | GND | 电源地 | GND | — | 必接 |
| 3 | LCD_CS | 屏幕片选 | **GPIO10** | `cs_pin` | |
| 4 | LCD_RST | 屏幕复位 | **GPIO8** | `reset_pin` | |
| 5 | LCD_RS / DC | 命令/数据 | **GPIO9** | `dc_pin` | 也叫 DC |
| 6 | SDI / MOSI | SPI 数据出 | **GPIO11** | `mosi_pin` | |
| 7 | SCK | SPI 时钟 | **GPIO12** | `clk_pin` | |
| 8 | LED | 背光控制 | **GPIO15** | 背光 PWM | PWM 20kHz，可实现熄屏调光 |
| 9 | SDO / MISO | SPI 数据入 | **GPIO13** | `miso_pin` | |
| 10 | CTP_SCL | 触摸 I2C 时钟 | **GPIO6** | `i2c: scl` | |
| 11 | CTP_RST | 触摸复位 | **GPIO5** | `reset_pin`（触摸） | |
| 12 | CTP_SDA | 触摸 I2C 数据 | **GPIO7** | `i2c: sda` | |
| 13 | CTP_INT | 触摸中断 | **不接**（可选） | — | 固件用轮询（20ms），不需要 INT；详见第七节 |
| 14 | SD_CS | TF 卡片选 | **预留 GPIO4** | — | v2.0 固件未启用 TF 卡；**必须 10k 上拉到 3.3V**，详见第七节 |

**共 12 根线**：电源 2 根 + SPI 4 根 + 屏幕控制 2 根 + 背光 1 根 + 触摸 3 根。

## 三、焊接注意事项

1. **VCC 一定接 5V**（开发板的 5V/VIN 引脚）。模组板载电平转换，3.3V 虽然能亮但背光明显偏暗，而且 ST7796S 在 3.3V 供电时部分批次会出现花屏。
2. **共地**：屏幕 GND 必须和开发板 GND 同一供电域，否则触摸 I2C 会随机漂移。
3. **SPI 四根线尽量短**（<10cm），杜邦线飞线时尤其注意 SCK（GPIO12）——40MHz 的时钟对线长敏感，太长会白屏或花条。
4. **CTP_INT 不用接**、**SD_CS 接 GPIO4 并加 10k 上拉**（见第七节），不要直接悬空。
5. 烙铁焊接排针时先焊**对角两针定位**，确认屏幕正对再焊其余，避免排针歪斜插不进面包板/洞洞板。

## 四、ESP32-S3 引脚占用与避让

本项目已占用：**GPIO5、6、7、8、9、10、11、12、13、15**。

如果你后续想加传感器/按键，避开以下引脚：

| 引脚 | 原因 |
|---|---|
| GPIO35 / 36 / 37 | **被 PSRAM 占用**（N16R8 是 octal PSRAM），绝对不可用 |
| GPIO0 | Boot 按键 / strapping，可用作输入但上电状态受影响 |
| GPIO3、45、46 | strapping 引脚，上电电平会被采样，接输出设备需谨慎 |
| GPIO19 / 20 | 板载 USB（Type-C 口就是走这两根），接了会抢 USB |
| GPIO43 / 44 | UART0 串口（看日志用），接外设后日志口失效 |

**推荐可用的剩余 GPIO**：1、2、4、14、16、17、18、21、38~42、47、48。

## 五、上电自检顺序

焊接完成后按这个顺序验证，出问题好定位：

1. **只接 USB，不接屏幕** → 能进系统、`esphome logs` 能看到日志
2. **接屏幕电源（VCC/GND）** → 屏幕背光微亮或不亮都正常（背光引脚还没接）
3. **接 SPI 5 根 + 控制线** → 屏幕应能显示界面（触摸可能还不灵）
4. **最后接触摸 3 根（SCL/SDA/RST）** → 触摸响应

常见故障速查：

| 现象 | 大概率原因 |
|---|---|
| 白屏 | 供电不足（3.3V 供电）或 RST/DC 接错 |
| 花屏/雪花条 | SCK 线太长或接触不良 |
| 显示正常但触摸无效 | SCL/SDA 接反，或 CTP_RST 没接 |
| 触摸坐标错位 | 正常现象，`transform` 已在固件里校正；若方向不对再改 `mirror_x/mirror_y` |
| 背光不亮 | LED（GPIO15）没接；或接了但固件亮度为 0 |

## 六、与固件的对应关系（备查）

```yaml
# ha-monitor-display.yaml 关键段
spi:
  clk_pin: GPIO12        # → 模组 7 脚 SCK
  mosi_pin: GPIO11       # → 模组 6 脚 SDI/MOSI
  miso_pin: GPIO13       # → 模组 9 脚 SDO/MISO

i2c:                     # 触摸 FT6336U @ 0x38
  scl: GPIO6             # → 模组 10 脚 CTP_SCL
  sda: GPIO7             # → 模组 12 脚 CTP_SDA

display:                 # mipi_spi / ST7796S
  cs_pin: GPIO10         # → 模组 3 脚 LCD_CS
  dc_pin: GPIO9          # → 模组 5 脚 LCD_RS
  reset_pin: GPIO8       # → 模组 4 脚 LCD_RST
  data_rate: 40MHz

output:                  # 背光 PWM
  GPIO15                 # → 模组 8 脚 LED

touchscreen:
  reset_pin: GPIO5       # → 模组 11 脚 CTP_RST
```

## 七、两个「预留脚」说明：CTP_INT 与 TF 卡槽

### 7.1 模组 13 脚 CTP_INT 是干什么的

FT6336U 的**中断输出**（Interrupt）：平时电平静默，手指按下/抬起时翻转一次，作用是「有事叫我」。
固件现在没接它，走的是 `touchscreen: update_interval: 20ms` **轮询** —— 每秒 50 次 I2C 去问芯片
「有没有人碰我」。两种方式功能等价，差别在成本和响应：

| | 轮询（现状） | 接 INT |
|---|---|---|
| 触摸响应延迟 | 最差 20ms（滑动时略有滞后感） | <5ms，跟手 |
| 空闲开销 | 每秒 50 次 I2C 唤醒，触摸芯片一直醒着 | 没人碰就完全静默 |
| 熄屏省电 | 想省电只能把轮询拉长，响应变差 | 可降到 200ms 甚至停掉，靠 INT 唤醒 |

**⚠️ 关键陷阱**：模组 13 脚**不能接 ESP32 的 GPIO13** —— GPIO13 已经被 SPI MISO（模组 9 脚）占了。
要接就选 GPIO16 / 17 / 21 / 38~42 里的一个空闲脚（避开 33~37 PSRAM、19/20 USB、43/44 串口、45/46 strapping）。

**结论：v2.0 不接。** 现在 20mA 的待机功耗里 WiFi 占大头，触摸轮询只是零头；
等以后真做「熄屏 + light-sleep」深度省电时，INT 才是必选项（ESPHome 的 `ft63x6` 支持 `interrupt_pin`）。

### 7.2 模组 14 脚 SD_CS：接，但暂不启用

TF 卡槽和屏幕**共用同一条 SPI 总线**（SCK/MOSI/MISO 已经通了），所以启用它只差 `SD_CS` 一根线。
现在接上是为了以后想用不用重新焊，固件里不配置它 —— **但有一步不能省：**

> **SD_CS 必须 10k 上拉到 3.3V。**

原因：SPI 模式下 CS 悬空，卡可能误判「自己被选中」，在 MISO（与卡 DAT0 共用）上抢总线。
屏幕初始化要读 ID，这时就会被顶掉，表现为**偶发白屏 / 花屏 / 开机不亮** —— 而且极难定位。
加了上拉，卡就固定处于「未被选中」状态，对屏幕零影响。

将来真要启用，两条路：
1. **flash 数据分区**（LittleFS / 自定义 partitions）—— 推荐。不耗电、不占总线、无卡座故障点。
2. 走 IDF 的 `sdspi` 挂到屏幕已初始化的 SPI2 上 —— ESPHome 没有官方 SD 组件，需要外部组件，属灰区，得实测。
